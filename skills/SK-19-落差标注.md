# SK-19 落差标注

## 何时用

S6 收尾。

## 输入 / 输出

- **输入**：落差项。
- **输出**：`{落差项, 落差值, 标注}`。

## 操作

1. **落差值**：按五点序数映射到数值范围。

| 序数标签 | 数值 |
|---|---|
| yes | **2** |
| maybe yes | **1** |
| not sure | **0** |
| maybe no | **−1** |
| no | **−2** |

2. **标注「有意／无意」**：
   - 文本内**有设计线索** → 可升级为硬判。
   - 文本内**无线索** → **只标注，不硬判**。

## 依据

| rule_id | 强度 | 原文要点 |
|---|---|---|
| P28-07 | necessary | MTurk 工作者对每个问题回答 yes／maybe yes／not sure／maybe no／no，「**作者把这个序数量表映射到数值范围，把标签分别映射为 2、1、0、−1、−2**」；同时「需要**丢弃非常含糊的样本**与那些可靠评分不足的样本」 |
| P28-05 | necessary | 「这些 trope 是**读者感知的**。它们**未必与创作者所意图的实际 trope 一致**。由于对已发布内容没有可量化的共识，我们把 TVTropes 数据当作角色归因的**噪声来源**」 |
| P24-09 | necessary | 不一致可被有意用于制造异化／知觉扰乱／陌生化／解构 |

## 依据分级

| 级 | 内容 |
|---|---|
| **【提取】** | P28-07 五点序数映射 2／1／0／−1／−2、须丢弃含糊样本；P28-05 判据是读者感知；P24-09 有意不一致 |
| **【设计决定】** | **「有文本内线索才升级为硬判」**这一门槛；「落差与严重度分开输出」 |
| **【自建】** | 无。**落差可服务于惊喜**为**人工裁定**（材料未直接支持，P24-09 提供部分依据） |

## 边界与失效条件

- **落差值 ≠ 严重度**。两者是**独立维度**，**不并入同一张量表**（SOP.md §1 不变量三）。
- **「刻意／无意」在缺乏文本内线索时只能是标注**——P28-05 裁定创作者意图不在证据里。把它当硬判就是用读者感知冒充作者意图。
- **必须丢弃含糊样本**（P28-07 原操作）。低可靠度的落差项应**丢弃**而非降权——含糊的落差项会污染整份报告。
- **「读者未表态」≠「读者答 not sure」**（E7 实跑校准）。P28-07 明令丢弃的是 **not sure（含糊样本）**；而**文本写了先验未预期的属性**（EXTRA 项）时，读者可能**根本没就此项表态**——那是**无数据**，不是**含糊数据**。
  - 无响应项**保留**，标 `no_response`，`drop_value = None`。
  - 归入「须丢弃」会**掩盖真正该报的落差项**（把一条明确落差变成"已丢弃"），从而**系统性低估落差**。
- **落差可服务于惊喜**。高落差不是缺陷信号；它是「读者会意外」的量化。**不要给它加负号。**

## 自检

- [ ] 落差值是否与严重度分开输出？
- [ ] 「有意／无意」是否只在有文本内线索时才硬判？
- [ ] 含糊的落差项（`not sure`）是否被丢弃而非降权？
- [ ] 无响应项是否与 `not sure` 分开处理（保留并标 `no_response`，而非一并丢弃）？
