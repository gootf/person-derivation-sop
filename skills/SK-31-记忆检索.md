# SK-31 记忆检索

## 何时用

S4。**在激活传播之前**——因为检索决定**哪些记忆进入可用集合**，而只有可用的记忆才参与激活。

回答的是 P19-21 留下的那个问题：知识库巨大，**「哪部分此刻被激活」**由什么决定。

## 输入 / 输出

- **输入**：查询（当前情境／当前关注）＋ 记忆流。
- **输出**：排序后的可用记忆子集（按分数降序，截断至容量）。

## 操作

### 一、三个部件

| 部件 | 作用 |
|---|---|
| **记忆流** | 以**自然语言**记录该人物经验的**完整清单** |
| **反思** | 随时间把记忆**综合成更高层推断** |
| **计划** | （第三部件） |

### 二、算三个分数

| 分数 | 算法 |
|---|---|
| **相关性** | 以查询记忆为条件——为该记忆与查询各生成嵌入向量，**相关性 = 两者嵌入的余弦相似度** |
| **新近性** | **自该记忆上次被检索以来、沙盒游戏小时数的指数衰减函数，衰减因子 0.995** |
| **重要性** | **在记忆对象创建时生成**——直接让语言模型输出一个 **1 到 10 的整数分** |

### 三、归一后加权组合

**把三个分数用 min-max 缩放到 [0, 1]，再按加权组合算出最终检索分数。**

> **实现取值**：原文**全部权重系数取 1**。

### 四、按容量截断

**排在前面的、能装入语言模型上下文窗口的记忆被写入提示。**

### 五、反思的触发（周期性）

| 项 | 值 |
|---|---|
| **触发条件** | 该人物**最近感知到的事件的重要性分数之和超过阈值**——**实现中为 150** |
| **实际频率** | 每人每天约 **2 到 3 次** |
| **首步** | 用记忆流中**最近 100 条记录**，向语言模型提出 **3 个最显著的待答问题** |

## 边界与失效条件

- ⚠️ **权重全取 1 是「实现取值」，不是理论结论**（P26-06 原话）。**不要把它当成最优权重**——原文说的是「实现中」如此。调权重须声明这是偏离原实现。
- ⚠️ **衰减因子 0.995 与阈值 150 都是单个实现的值**。P26-03 说新近性「**被实现为**」该函数、P26-07 说阈值「**实现中为** 150」——**都是该系统的工程选择**，不是从理论导出的常数。**不得把它们当作普适参数。**
- ⚠️ **成本是实测的**（P26-14）：「模拟 **25 个人物两天消耗了数千美元** token 额度并**耗时数日**」。**本技能是四个环里成本最高的一环**；全量运行前须评估规模。
- **相关性是「以查询为条件」的**（P26-05）。**同一个记忆在不同查询下的相关性不同**——不要把相关性当记忆的固有属性缓存起来。
- **重要性在创建时定，之后不变**（P26-04）：它是**创建时刻的一次性判断**，不随检索历史更新。**不要按「被检索次数」动态提升重要性**——那是自建行为。
- **新近性从「上次被检索」起算，不是从「事件发生」起算**（P26-03 原文：「自该记忆**上次被检索**以来」）。**用事件时间戳会算错。**
- **反思产出是「更高层推断」**（P26-01）：它是**从记忆综合出的新内容**，**不是原记忆**。这些推断在后续检索中与原始记忆并列，**必须标记来源**，否则会把推断当事实。
- **截断按容量，不按阈值**（P26-15）：「能装入上下文窗口」——**分数低但仍在容量内的会被写入**。

## 自检

- [ ] 三个分数是否都算了？相关性是否以查询为条件？
- [ ] 新近性是否从「上次被检索」起算（而非事件时间）？
- [ ] 重要性是否是创建时的一次性判断？
- [ ] 反思产出是否标记为「推断」而非「记忆」？
- [ ] 是否声明了权重取 1、0.995、150 这三个值都属实现选择？
- [ ] 规模与成本是否评估过（P26-14 的实测）？
