# SK-22 事件情绪推导

## 何时用

S4。评价向量已得出，需要**把评价转成情绪标签与强度**时。

**只适用于 12 个「事件型」情绪**——即仅依赖「事件对目标的意义」的那些。其余情绪需要角色对事件与对象的标准与态度，**高度域依赖**，本技能不覆盖。

## 输入 / 输出

- **输入**：事件 + 人物的效用函数 + 预期计划集合。
- **输出**：情绪标签 + 强度。

## 操作

### 第一步：定事件的三个属性

| 属性 | 取值 |
|---|---|
| **确认状态** | 未确认（预期可能发生）／已确认（实际观察到发生）／已取消（**不再被预期发生**） |
| **理想性** | 理想（达成目标、提高效用）／非理想（导致目标失败、降低效用） |
| **涉及对象** | 自身 ／ 朋友 ／ 非朋友 |

### 第二步：查表定标签（12 情绪全表）

| 情绪 | 前景（确认状态 × 理想性） |
|---|---|
| **Joy** | 理想事件发生（前景无关） |
| **Distress** | 非理想事件发生（前景无关） |
| **Hope** | **未确认** + 理想 |
| **Fear** | **未确认** + 非理想 |
| **Satisfaction** | **已确认** + 理想 |
| **Fears-Confirmed** | **已确认** + 非理想 |
| **Disappointment** | **已取消** + 理想 |
| **Relief** | **已取消** + 非理想 |
| **HappyFor** | 对**朋友**理想的理想事件 |
| **Resentment** | 对**朋友**理想的非理想事件 |
| **Gloating** | 对**非朋友**不理想的理想事件 |
| **Pity** | 对**非朋友**不理想的非理想事件 |

### 第三步：状态转移

| 前态 | 事件发生（被确认） | 事件不发生（被取消） |
|---|---|---|
| **Hope** | → **Satisfaction** | → **Disappointment** |
| **Fear** | → **Fears-Confirmed** | → **Relief** |

### 第四步：算强度

| 情绪 | 强度 |
|---|---|
| **Joy** | 效用增加幅度 `U(c,s) − U(c,s')` |
| **Distress** | 效用下降幅度 |
| **Hope** | `U(c, s) − h_u`，其中 **`h_u = U(c, α(π, β(c, s)))`** 是**希望效用**——预期计划集合中**可达的最高效用**，且须 `h_u > U(c, s)` |
| **Fear** | 由预期计划集合中的**最低可达效用** `f_u < U(c,s)` 定义 |
| **Satisfaction** | **继承对应 Hope 的强度** |
| **Fears-Confirmed** | **继承对应 Fear 的强度** |
| **Relief** | **对应 Fear 强度的倒数** |
| **Disappointment** | 见 Hope 的对称侧 |

**关键区分**：「意外」与「预期」是这套定义的关键判据——**被一个提高效用的行动所惊讶，感到的是 Joy 而非 Satisfaction**。

## 判据要点（先看这条，再看表）

**判据是「效用差」，不是「评价维度」。**

1. **情绪标签绑定在人物自身效用的变化上**：效用**上升** → Joy；**下降** → Distress。
2. **强度 = 效用的变动幅度**（Joy／Distress 用 `U(c,s) − U(c,s')`；Hope／Fear 用 `U(c, s) − h_u`）。
3. **前摄类（Hope／Fear）必须先构造 expected plan 集合**——Hope 取「效用高于当前的**最高**可达效用」，Fear 取「**最低**可达效用」。
4. **「意外」与「预期」是区分 Joy 与 Satisfaction 的关键判据**：被意外提升效用**只给 Joy，不给 Satisfaction**。

## 边界与失效条件

- ⚠️ **强度公式不等于理论结论**。P17-04 明写：「OCC 情绪触发与规划触发之间是一一对应，但**强度定义是作者直觉给出的，非从 OCC 推导**」。**触发是理论推导的，强度是作者规定的。** 输出强度时必须带上这一限定，不得声称强度有 OCC 理论支持。
- ⚠️ **`U` 与 `π` 是本技能链的最大缺口**。强度公式全部建立在 `U(c, s)`（人物效用）与预期计划集合 `π` 之上——**材料给了公式，没有给 `U` 与 `π` 的定义方式**。使用前必须先声明这两者从何而来，否则强度值不可复现。
- **只覆盖 12 个情绪，不要外推**。其余依赖标准与态度的情绪**高度域依赖**（「在野蛮的维京世界中，杀人可能被视为值得称赞」），**不可无域依赖地移植**。
- **「已取消」是改写过的定义**。P16-06 原作者**明确改写了 OCC 的定义**：「由于没有跟踪时间的规划结构，我把『已取消事件』的定义改为『当该事件不再被预期发生』」。引用时须说明这是改写版，不是 OCC 原义。
- **预期不唯一**（P16-08）：人物可预期**多个序列**，`h_u` 取其中**最高可达效用**。不要把人物当成只有一条预期路径。
- **惊讶不给 Satisfaction**（P16-12）：被提高效用的行动所惊讶 → Joy。区分「意外」与「预期」是核心判据，两个情绪**不可互替**。
- **Relief 的强度是倒数**——这条形式特殊（其余情绪用差值或继承），**不要按对称性臆造**。
- **不要从情绪名反推事件属性**。表是**生成方向**（事件属性 → 情绪），不是识别方向。
