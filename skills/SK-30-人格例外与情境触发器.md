# SK-30 人格例外与情境触发器

## 何时用

S2 建图或 S4 激活时。**当文本显示某属性「一般成立，但遇到某种情况就不成立（或更强烈）」时。**

**这是「情境依赖」这一强度档（SK-17）的机制来源**——没有本技能，`情境依赖` 只能靠感觉给。

## 输入 / 输出

- **输入**：某属性 ＋ 它的例外情形。
- **输出**：**人格例外二元组**（情境触发器，人格修正效果）。

## 操作

### 一、写成二元组，不要写成两个独立断言

| 元件 | 内容 |
|---|---|
| **情境触发器** | 什么条件 |
| **人格修正效果** | 该条件下属性如何被修正 |

**它不是一个属性，是一对（触发器，修正）。** 拆成两条独立断言会丢掉「只在遭遇触发器时生效」这一关键约束。

### 二、触发条件用「事件显著度」表述，不用「情境类别」

**触发条件由角色内部记忆的事件显著度给出，而非外部情境类别。**

### 三、按六个索引表述触发条件

| 索引 | 覆盖 |
|---|---|
| **time** | 时间 |
| **space** | 空间 |
| **protagonist** | 施事者 |
| **proposition** | 命题 |
| **action** | 行动 |
| **intention** | 意向 |

**用这六个索引组合来描述「什么算遭遇了该触发器」**，而不是用「在酒吧里」这类外部类别。

### 四、只在遭遇触发器时生效

**未遭遇触发器时，该修正不生效**——属性按基本形态使用。

## 依据分级

| 级 | 内容 |
|---|---|
| **【提取】** | P18-01 二元组定义与生效条件；P18-02 触发条件的判据与六索引；P20-09 的改变实例（新目标获得更高激活准备度、与高唤醒情境的连接减弱） |
| **【设计决定】** | 把「二元组 → 显著度表述 → 六索引 → 生效条件」组织为**四步操作顺序** |
| **【自建】** | 六索引的**具体取值域**——材料只列出六个索引名，未给每个索引的可选值 |

## 边界与失效条件

- ⚠️ **触发条件是内部显著度，不是外部情境类别**（P18-02）。**「在酒吧里」不是触发器**——触发器是「该人物记忆中某事件被感知为显著」。用外部类别会系统性地错判：同类外部情境对不同人物不构成同一触发器。
- **修正方向可以是双向的**（P20-09）：孩子出生后，某些 PCC 激活准备度**升高**，另一些连接**减弱**。**不要只建「减弱」这一侧。**
- **例外不是矛盾**（这是与 SK-10 的关键分界）：带触发器的修正与基本属性**不是符号冲突**——因为它们在**不同条件下生效**。**若一条修正被当成对基本属性的负向入边，会被 SK-10 误报为 F2。**
- **六索引不是完备描述**。材料只列了六个索引名，**未给每个索引的取值域**；用它们表述触发器时须**同时给出自然语言描述**，否则不可复核。
- **例外不改变「有该属性」这一判断**。它改变的是**该条件下属性如何表现出来**——**不要把例外当成属性被否定。**

## 自检

- [ ] 例外是否写成了**二元组**（而非两条独立断言）？
- [ ] 触发条件是否用「事件显著度」而非外部情境类别表述？
- [ ] 是否用六索引标定了触发条件？
- [ ] 修正方向是否检查了双向（升高与减弱）？
- [ ] 是否会被 SK-10 误报为 F2？（检查：符号冲突 vs 条件修正）

## 附：与强度档「情境依赖」的接口

本技能产出的二元组是 SK-17 判 `情境依赖` 的依据。**输出 `情境依赖` 时，「条件」部分必须随判定一起给出**（SK-17 边界）——那个条件就是本技能的触发器。
